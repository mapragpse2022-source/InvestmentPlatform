# 1. Purpose

This document defines how investment performance calculations are created, stored and presented within the Digital Investment Platform.

---

# 2. Profit Calculation Philosophy

The platform separates:

- Investment Principal
- Expected Performance
- Calculated Performance
- Paid Performance

These values must never be mixed.

---

# 3. Profit Record Concept

Every calculated performance result must create an independent Profit Record.

A Profit Record represents a financial event related to an investment.

---

# 4. Profit Record Data

Each Profit Record should contain:

- Investment reference
- User reference
- Calculation period
- Calculation date
- Amount
- Calculation status
- Creation timestamp

---

# 5. Performance Types

The system supports:

## Expected Performance

A projection shown to users based on current investment rules.

This value is informational.

---

## Calculated Performance

A value generated by the financial calculation engine.

This value becomes part of financial history.

---

## Paid Performance

A value that has been transferred or settled according to platform rules.

---

# 6. Calculation Engine Rules

The calculation engine must:

- Use approved investment rules.
- Produce traceable results.
- Store calculation history.
- Avoid direct balance modification.

---

# 7. Calculation Frequency

The system architecture must support configurable calculation periods.

Examples:

- Daily
- Weekly
- Monthly

The selected period depends on the approved investment plan.

---

# 8. Investment Performance Formula

The calculation engine should support configurable formulas.

Example structure:

Investment Amount

×

Performance Rate

×

Applicable Period

=

Calculated Performance

---

# 9. Example Investment Rule

Example:

Investment Amount:

100 USDT

Performance Rule:

15 USDT monthly expected performance

This example represents an investment plan configuration and must not be hardcoded into application logic.

---

# 10. Profit Status

Profit records may have:

## Pending

Calculation created but not finalized.

---

## Calculated

Calculation completed and recorded.

---

## Settled

Processed according to settlement rules.

---

## Cancelled

Invalidated according to approved procedures.

---

# 11. Financial Integrity Rules

The system must:

- Never delete historical profit records.
- Never silently modify calculations.
- Maintain audit history.

Any correction must create a new adjustment record.

---

# 12. User Dashboard Requirements

Users should be able to view:

- Investment amount
- Performance history
- Calculated values
- Settled values
- Dates of calculations

---

# 13. Administrative Reporting

Administrators should access:

- Total calculated performance
- Total settled performance
- Investment performance reports
- Historical calculations

---

# 14. Security Requirements

Profit calculations must be protected against:

- Unauthorized modification
- Manual manipulation
- Incorrect recalculation

Sensitive operations require audit logging.

---

# 15. Future Extensions

The architecture should support:

- Multiple investment products
- Different performance models
- Automated financial reports
- Advanced analytics

---

# 16. AI Implementation Notes

AI coding assistants must:

- Never create financial formulas without documentation.
- Keep calculation logic separated from user interface.
- Preserve financial history.
