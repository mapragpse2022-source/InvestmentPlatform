# 1. Purpose

This document serves as the central entry point for all project documentation.

It defines the documentation structure, organization principles, document ownership, and navigation across the repository.

Every contributor, architect, developer, designer, and AI coding assistant should begin here before reading any other documentation.

---

# 2. Documentation Philosophy

The project follows a **Documentation Driven Development (DDD)** approach.

All major decisions must be documented before implementation.

Documentation is considered part of the source code and must evolve together with the system.

# 5. Documentation Rules

Every document must include:

- Document ID
- Version
- Status
- Owner
- Last Updated
- Depends On
- Used By
- Related Documents
- Revision History

---

# 6. Document Status

Documents may have one of the following statuses:

- Draft
- Review
- Approved
- Deprecated

---

# 7. Versioning

Version format:

MAJOR.MINOR.PATCH

Example:

1.0.0

---

# 8. AI Guidelines

AI coding assistants must:

- Read related documents before implementation.
- Follow documented architecture.
- Never modify architecture without updating documentation.
- Respect coding standards.
- Maintain cross-document consistency.
